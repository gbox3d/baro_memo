# 토큰 — 발급·확인·폐기

토큰을 손으로 다루는 절차입니다. 토큰 API 자체의 계약(라우트·본문·거절 코드 전문)은 서버가
서빙하는 `GET /memo/api/help/tokens` 가 정본이라 여기서 옮겨 적지 않고, 팀 소속은
[teams.md](./teams.md), 팀원 기기에 붙이는 절차는 [agents.md](./agents.md), 재시작은
[operations.md](./operations.md) 에 있습니다.

## 값이 둘 있습니다

**사람 토큰**(`bm_…`)은 관리자가 사람마다 발급하고, 서버가 그 값에서 글의 `user` 를 찍습니다.
**관리자 토큰**(`adm_…`)은 배포마다 하나이고 관리자 페이지와 `/api/admin/*` 이 씁니다.

읽기에도 토큰이 필요하며 둘 중 아무 유효한 값이나 됩니다. 쓰기는 사람 토큰만입니다 — 관리자
토큰에는 찍을 사람이 없어 403 `admin_token_cannot_write` 입니다. 아티팩트 저장소도 같은 값을
씁니다. 발급처가 한 곳이라 폐기도 한 번이면 끝입니다.

## 관리자 토큰

값과 **그 값을 읽어 온 파일 경로**를 같이 봅니다.

```bash
pnpm admin:token
```

```
관리자 토큰: adm_…
파일:        /mnt/data/baro_memo_db/admin-token
관리자 페이지: /memo/admin/
```

경로를 외워 `cat` 하는 절차를 없애려는 것이자, 기동 로그의 `admin=configured (<경로>)` 와 같은
경로인지 맞춰 보는 수단입니다 — 고친 파일과 서버가 읽은 파일이 갈라진 것이 이 종류 설정의 가장
흔한 사고입니다. 파일이 없으면 만들어 주고 권한 600 으로 둡니다. 정본은 `.env` 의
`ADMIN_TOKEN_FILE` 이며 그 줄이 있으면 `ADMIN_TOKEN` 환경변수는 무시됩니다(근거는
[../.env.example](../.env.example) 주석). `ADMIN_TOKEN_FILE` 이 없는 배포에서는 이 스크립트가
아무것도 하지 않고 그 사실을 말하고 끝냅니다.

**교체는 `pnpm admin:token --rotate` 이고, 서버를 재시작해야 반영됩니다.** 서버는 부팅 때 이
파일을 한 번만 읽습니다 — 재시작 전까지 관리자 페이지에서 통하는 것은 **옛 값**이고 새 값은
401 입니다. 처음 만들 때도 같습니다. 교체와 재시작 사이를 짧게 잡으십시오.

배포에 관리자 토큰이 아예 없으면 관리 라우트가 503 `admin_token_unset` 으로 답합니다. 보드
읽기·쓰기는 그와 무관하게 계속 됩니다 — 자격증명 하나 때문에 보드를 멈추지 않습니다.

## 사람 토큰 — 관리자 페이지에서

`/memo/admin/` 의 「토큰」 구획입니다. 리스트에는 상태만(사용자·앞 10자·메모·발급 시각·폐기
여부) 있고, 액션은 리스트 위 속성창에 있습니다.

- **발급** — 사람 이름을 넣고 발급합니다. 그 이름이 곧 그 사람의 글에 찍히는 `user` 입니다.
  사람마다 하나씩 주고 공유하지 않습니다. 공유하는 순간 `user` 가 다시 추측이 됩니다.
- **재조회** — 한 줄을 고르면 전문과 「복사」가 나옵니다. 서버가 값을 그대로 보관하므로
  **잃어버린 토큰은 재발급할 것 없이 다시 꺼내 보면 됩니다.** 재발급은 사람이 바뀌거나 값이
  샜을 때 하는 일입니다.
- **전달** — 「메시지」가 국/영 안내문을 만들어 줍니다. 화면에서 고칠 수 있고 복사되는 것은
  화면의 값입니다. 그 안의 주소는 서버가 알려 준 `RELEASE_BASE_URL` 이라, 사내망 IP 로 이
  페이지를 열어 두고 밖에 있는 사람에게 보내도 밖에서 닿는 주소가 실립니다.
- **폐기** — 그 순간부터 401 입니다. 유예도 캐시도 없어서 다운로드(`/files/dl/…`)까지 같이
  막힙니다. 행은 남습니다 — 옛 글의 귀속이 그대로 있어야 하기 때문입니다.

팀 소속은 토큰이 아니라 **사람 이름**에 걸립니다. 폐기하고 다시 발급해도 그 사람의 팀은
그대로입니다([teams.md](./teams.md)).

## 가진 값이 맞는가

값을 보는 곳과 그 값이 맞는지 보는 곳이 다릅니다. 서버는 어느 쪽도 되읊어 주지 않고 거절 코드로만
답하므로, **물어보는 것이 확인입니다.**

```bash
read -rsp '토큰: ' T; echo
B=http://192.168.0.220/memo            # 밖에서는 http://gobackdev.iptime.org:22030/memo
curl -s -H "x-memo-token: $T" $B/api/auth/whoami
```

| 돌아온 것 | 뜻 | 고칠 사람 |
|---|---|---|
| 200 `{"user":"이름","admin":false}` | 그 사람의 토큰입니다. 읽기·쓰기 다 됩니다 | — |
| 200 `{"user":null,"admin":true}` | 관리자 토큰입니다. 읽기는 되고 글은 못 씁니다 | — |
| 401 `memo_token_invalid` | 토큰들은 있는데 이 값이 아닙니다 (틀렸거나 폐기됨) | 가진 쪽 |
| 503 `no_tokens_issued` | 이 배포에 발급된 값이 0개입니다. 어떤 값을 넣어도 안 됩니다 | 운영자 |

함께 오는 `teams` 는 **유효 도달 범위**입니다 — `super` 인 사람에게는 소속 행 둘이 아니라 팀
전부가, 관리자 토큰에는 "전부"를 뜻하는 `null` 이 실립니다([teams.md](./teams.md)).

관리자 토큰은 한 걸음 더 봅니다. 위 표의 `admin:true` 는 서버가 그 값을 알아본다는 뜻이고,
관리 라우트가 서는지는 그 라우트가 답합니다.

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H "x-memo-token: $T" $B/api/admin/tokens
```

`200` 이면 됩니다. `401 admin_token_invalid` 는 설정은 돼 있는데 이 값이 아니라는 뜻이고,
`503 admin_token_unset` 은 이 배포에 관리자 토큰이 없다는 뜻입니다 — 이 503 은 위의 whoami 로는
갈라지지 않습니다(미설정이면 어떤 값도 관리자 토큰으로 안 보여 401 로 떨어집니다).

에이전트 쪽은 같은 확인을 빈 본문 `POST /api/memos` 로 합니다. 인증이 본문 검사보다 **먼저**
돌기 때문에 400 `empty_body` 가 돌아오면 통과이고, 보드에는 아무것도 남지 않습니다. 스킬이
처음 불릴 때 스스로 돌리므로 사람이 대신 할 일은 아닙니다([agents.md](./agents.md)).

**값은 명령줄에 직접 박지 않습니다.** 셸 히스토리와 대화록에 남고, 그 둘은 지우기 어려운 자리에
오래 남습니다. 확인할 때도 위처럼 변수로 넘깁니다. 팀원 기기의 값은 같은 이유로
`~/.config/baro-memo/env`(권한 600) 에 들어갑니다.
