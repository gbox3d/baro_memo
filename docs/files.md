# 아티팩트 저장소 — 디스크와 수명

연구실 사이로 수 GB 짜리 릴리스를 나르는 자리입니다. 보드와 **같은 프로세스**가 들고, 토큰도
보드 것을 그대로 씁니다.

이 문서는 디스크 쪽만 맡습니다 — 바이트가 어디 앉고, 무엇이 자동으로 지워지고, 볼륨이 안 붙은
아침에 무엇이 보이는가. 올리고 받는 방법(세션·청크·재개·Range·거절 코드)과 무엇을 여기 두고
무엇을 두지 않을지의 판단은 `GET /files/api/help` 가 정본이라 옮겨 적지 않습니다.

주소가 두 벌인 것을 먼저 알아 두십시오. 밖에서 보이는 것은 `/files/api/…` 이고, 호스트에서
백엔드를 직접 부를 때는 `/api/files/…` 입니다(nginx 가 접두사를 바꿔 줍니다). 아래 명령은 전부
직접 부르는 쪽이고, 포트는 `.env` 의 `PORT` 입니다 — 이 호스트는 3001.

## 바이트는 그냥 파일입니다

`FILES_ROOT`(이 호스트는 `/mnt/data/baro_memo_files`) 밑이 전부입니다. DB 에는 장부만 있습니다.

```
files.db          장부 — 완성본과 진행 중 세션
store/<sha256>    완성본. nginx 가 alias 로 디스크에서 바로 내보냅니다
tmp/<세션id>       진행 중. 선언 크기로 미리 뚫린 희소 파일이고 청크는 제자리에 앉습니다
```

두 값이 **같아야** 합니다: `.env` 의 `FILES_ROOT` 와 `deploy/nginx-baro-files.conf` 의 `alias`
뿌리. 한쪽만 바꾸면 업로드는 되는데 다운로드가 404 입니다(proxy_pass 포트↔`PORT` 와 같은 종류의
결합). 서버가 실제로 읽은 뿌리는 기동 로그 둘째 줄이 찍습니다.

```
[baro_memo/files] mounted at /api/files · root=/mnt/data/baro_memo_files
```

권한도 계약입니다 — `store/` 는 755, 완성본은 644, www-data 가 읽습니다. 백엔드가 만들 때
챙기므로 평소에 손댈 일은 없지만, 볼륨을 옮기거나 복사할 때는 보존해야 합니다.

## 디스크

보드 DB 와 **같은 볼륨**입니다(이 호스트는 `/mnt/data`, 11 TiB). 아티팩트가 볼륨을 바닥내면
보드까지 멎으므로 여유를 지키는 것이 저장소 쪽의 의무이고, 세 한도가 코드 상수로 박혀 있습니다
(`apps/files/src/files/store.mjs` 의 `LIMITS` 가 정본 — 설정으로 뺀 값이 아닙니다).

| 한도 | 값 | 넘으면 |
|---|---|---|
| 볼륨 여유 예약 | 20 GiB | 507 `insufficient_storage` |
| 사람당 | 1 TiB | 403 `quota_exceeded` |
| 파일 하나 | 50 GiB | 400 `invalid_size` |

사람당 몫은 **완성본 + 진행 중 세션의 선언 크기**입니다. 받은 만큼이 아니라 선언 크기로 세므로,
버려 둔 세션은 남의 몫이 아니라 자기 몫을 먹습니다. 여유 예약은 세션을 열 때 한 번, 그리고
청크마다 다시 확인합니다 — 희소 파일이라 여유는 업로드가 차오르는 동안 계속 줄어듭니다.

지금 상태는 토큰 없이 볼 수 있습니다.

```
curl -s localhost:3001/api/files/health
{"ok":true,"version":"0.13.1","store":{"artifacts":2,"bytes":2799150588,"openUploads":0,"freeBytes":11901558382592}}
```

## 무엇이 자동으로 지워지나

- **유령 세션** — 마지막 청크가 *시작된* 때로부터 48시간이 지난 업로드. 기동 때 한 번, 이후 한
  시간마다 돕니다. 지금 청크가 흐르는 세션은 건너뜁니다. 연구실 간 링크에서 몇 시간짜리 스트림은
  정상 운행이라 시한이 넉넉합니다.
- **장부가 가리키지 않는 `store/` 파일** — 기동 때 화해 절차가 지우고 로그에 남깁니다
  (`[baro_files] recover: removed ghost <sha256>`). 목록에는 없는데 다운로드만 되는 바이트가
  최악이라서입니다.

**완성본은 어느 쪽으로도 지워지지 않습니다.** 발행된 것에는 만료가 없습니다.

그래서 백업에 순서가 있습니다: `files.db` 와 `store/` 는 **함께** 백업하고 함께 복구합니다.
장부만 잃고 바이트를 살려 두면 다음 기동의 화해 절차가 `store/` 를 통째로 유령으로 보고
지웁니다. 보드 DB 쪽 백업은 [operations.md](./operations.md) 에 있습니다.

## 지우기

발행자 본인, 또는 운영자(관리자 토큰)만 지웁니다. 관리자 페이지에는 이 화면이 없어 API 로
합니다 — 토큰 값을 명령줄에 박지 않는 방법은 [tokens.md](./tokens.md) 와 같습니다.

```
curl -s -H "x-memo-token: $T" localhost:3001/api/files/artifacts
curl -s -X DELETE -H "x-memo-token: $T" localhost:3001/api/files/artifacts/<sha256>
```

`{"deleted":true,"sha256":"…"}` 가 아니면 다음으로 가지 않습니다. 403 `not_your_artifact` 는
남의 발행본을 사람 토큰으로 지우려 한 것이고, 관리자 토큰으로는 지나갑니다.

지운 뒤에는 **보드에 글을 남깁니다.** 누군가의 파이프라인이 그 URL 을 아직 가리키고 있을 수
있고, 알릴 곳은 보드뿐입니다. 내용 주소라 같은 바이트를 다시 올리면 같은 URL 로 되살아납니다.

## 볼륨이 안 붙었을 때

저장소만 죽고 **보드는 삽니다**. 대신 증상이 자리마다 다르게 보입니다.

| 어디 | 무엇이 보이나 |
|---|---|
| 기동 로그 둘째 줄 | `[baro_memo/files] UNAVAILABLE — <이유>` |
| 보드 `GET /memo/api/health` | `"files": "unavailable: <이유>"` (성하면 `"mounted"`) |
| 저장소 API | 전부 503 `store_unavailable` |
| 다운로드 `/files/dl/…` | 503 `identity_unavailable` |

마지막 줄이 함정입니다. 다운로드는 nginx 의 `auth_request` 가 백엔드에 토큰을 물어보고
통과시키는데, 마운트가 죽으면 그 확인도 503 이라 nginx 규칙상 500 이 되고 conf 가 그것을
`identity_unavailable` 로 되돌려 줍니다. **코드 이름만 보고 토큰을 의심하지 마십시오** — 보드
health 의 `files` 칸이 먼저입니다.

조치는 볼륨을 붙이고 **보드를 재시작**하는 것입니다. 마운트는 기동 때 한 번만 열고 스스로
재시도하지 않습니다. 확인은 health 의 `files` 칸이 `"mounted"` 로 돌아오는 것이고, 그전에는
다음으로 가지 않습니다.

## 재시작과 전송 중인 업로드

한 프로세스라 보드를 재시작하면 **전송 중인 업로드가 끊깁니다**(다운로드도 몇 초 끊깁니다 —
무엇과 맞바꾼 것인지는 `GET /files/api/help`). 재개가 있어 올리는 쪽의 대가는 "명령 한 번
다시"지만, 재시작 전에 창을 봅니다.

`health` 의 `store.openUploads` 는 지금 흐르는 청크가 아니라 **열려 있는 세션 전부**입니다 —
사흘째 놀고 있는 세션도 셉니다. 그래서 0 이 아니라고 무작정 기다릴 것이 아니라, 세션 목록의
`lastActivity` 를 보고 판단합니다(관리자 토큰이면 전원의 것이 보입니다).

```
curl -s -H "x-memo-token: $T" localhost:3001/api/files/uploads
```

배포 절차 자체는 [operations.md](./operations.md) 에 있습니다.

## 이 저장소가 아닌 것

한 번 건네고 금요일에 죽을 덤프는 여기가 아닙니다 — 세션도 해시 선언도 영구 자리도 필요 없는
바이트라서요. 판단 기준과 대안은 `GET /files/api/help` 의 "When not to use this" 에 있고,
사람이 그것을 물어 오면 그 절을 가리키면 됩니다.
